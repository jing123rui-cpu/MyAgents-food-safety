# 整改建议（corrective_action）

**状态**：已实现 · **阶段**：5 - 整改要求

## 用途

为每条不符合项生成整改要求，包含原因分析、立即纠正、预防措施、责任方、时限。

## 引擎实现

| 组件 | 路径 | 职责 |
|---|---|---|
| 写作引擎 | `audit/script/ai/writing_engine.py`（`generate_corrective_action`） | 组装上下文、生成整改文本 |
| 提示词 | `audit/script/ai/prompts.py` | 整改类提示词模板 |
| 降级 | 同上（离线分支） | 无 API 时输出确定性中文模板 |

## 输入 / 输出

- 输入：`evaluation_results`（不符合项）、`inspection_context`（证据、检查点、风险数据）
- 输出：`corrective_requirements`（报告第 8 节「整改要求」文本）

## 在对话中的用法

每条整改必须包含五要素，缺一不可：

| 要素 | 要求 | 反例 |
|---|---|---|
| 立即纠正 | 本次问题怎么处理 | 「加强管理」 |
| 纠正措施 | 如何防再发（改流程/改文件/改设施） | 只写「培训员工」 |
| 责任方 | 部门或岗位 | 「相关部门」 |
| 时限 | 具体日期或天数 | 「尽快」 |
| 验证方式 | 用什么证据证明改好了 | 「自查」 |

模板：

```markdown
### 不符合项 N：{一句话标题}
- 立即纠正：{封存/停用/召回评估/返工}，{完成时间}
- 原因分析：{直接原因 → 根本原因}
- 纠正措施：{文件修订/工艺调整/设施改造/供应商处置}
- 责任方：{部门/岗位}
- 完成时限：{YYYY-MM-DD}
- 验证方式：{记录复查/现场复核/抽样检验}，验证证据：{记录编号/照片编号}
```

## 局限

- AI 生成的整改建议依赖提示词质量，离线模式为固定模板，针对性弱。
- 不跟踪 CAPA 生命周期（验证、关闭），输出只是建议文本。
- 涉及许可变更、配方变更的整改，需另行评估是否需要变更申请。
