# 报告生成（report_generation）

**状态**：已实现 · **阶段**：6 - 报告输出

## 用途

把检查结果写成 12 节监管格式中文报告，并导出 Word（.docx）。

## 引擎实现

| 组件 | 路径 | 职责 |
|---|---|---|
| 写作引擎 | `audit/script/ai/writing_engine.py` | 生成 12 节内容（AI 或离线模板） |
| 导出器 | `audit/script/ai/report_exporter.py` | 转 docx，含页码、表格边框、结论配色、时间戳文件名 |

## 12 节结构

1. 企业基本信息 2. 检查概况 3. 检查依据 4. 检查方法与范围 5. 检查情况统计
6. 发现项 7. 法规引用 8. 整改要求 9. 风险分析 10. 结论 11. 建议 12. 附件

## 输入 / 输出

- 输入：`AuditWritingResult`（12 节内容）、`enterprise_info`（企业名称、类型、检查人、检查日期）
- 输出：`.docx` 路径、`ReportExportResult`（文件名、生成时间、成功标志）

## 在对话中的用法

1. **正式报告**优先用 `references/report-template.md` 的骨架，与引擎 12 节对位。
2. 需要生成 docx 时：
   ```bash
   cd audit
   python demo_export.py        # 会写出 docx，执行前说明输出目录
   ```
3. 报告写作三条硬规则：
   - 事实与判断分离（事实节只写观察到的，判断节才写定性）
   - 每条事实可追溯到照片编号/记录页码/访谈对象
   - 引用条款写全称与条号，不确定标 `【需核对原文】`
4. 不写行政处罚决定；涉及吊销、罚款等表述改为「建议依法进一步调查处理」。

## 局限

- 输出格式固定，属地监管有专用模板时以监管模板为准。
- AI 生成段落需人工校对，尤其数字、日期、条款号。
- 导出为写操作，执行前须说明输出路径。
